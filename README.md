# 渠道贡献归因工作台（Channel Attribution Workbench）

面向电商投放分析师与投放负责人的**渠道贡献分析与订单回查**前端应用。基于 React 18 + TypeScript + Vite + ECharts 实现，纯前端工程（无后端依赖，数据服务以异步模块模拟），所有运行、共享与预算方案通过 `localStorage` 持久化。

> 所有归因结果都是**规则分摊**，用于渠道间相对比较与订单级回查，**不代表渠道因果关系**。

---

## 1. 技术栈

| 层 | 选型 |
| --- | --- |
| 框架 | React 18 + TypeScript 5（strict） |
| 构建 | Vite 5 |
| 图表 | Apache ECharts 5（独立分包） |
| 路由 | react-router-dom 6（HashRouter，兼容静态托管） |
| 状态 | zustand 4（persist 中间件，localStorage） |
| 时间 | dayjs + 原生 `Intl` 时区格式化 |
| 测试 | Vitest（引擎纯函数 / 竞态 / 存储工作流 / SSR 冒烟） |
| 部署 | 多阶段 Dockerfile + docker-compose（nginx 托管 SPA） |

金额全部以**整数分**存储与计算，展示层格式化为元，杜绝浮点误差。

## 2. 本地启动

### 2.1 开发模式

```bash
npm install --no-audit --no-fund
npm run dev
# 打开 http://localhost:5173
```

### 2.2 生产构建与本地预览



> 说明：当前隔离沙箱内 Docker daemon 不可用，容器镜像未在本环境实际构建；`npm run build` 产物与 nginx 配置均已通过静态检查，Dockerfile/compose 语法为标准多阶段写法。


## 4. 推荐验证路径（覆盖全部需求场景）

### 场景 0：准备一个已锁定运行（后续验证的前置）

1. 以「林岚」身份进入 **归因运行** 页，保持默认配置（快照 `DS-2026-11-01` / 净额口径 / 7 天窗口 / 末次触点），点击「创建草稿运行」→「执行计算」。
2. 顶栏切换为「赵明」→ 在运行行点击「审批核对」→ 修订一致后「锁定」。

### 场景 1：跨设备未授权不拼人（授权边界）

- **数据接入与血缘** 页 → ②身份授权表：`P-1003 王芳` 标注「未授权」，两台设备 `D-C1/D-C2` 虽有相同 `email_hash` 也不合并。
- **渠道贡献报告** 页选上述运行，点击订单 `O-2007` 行：抽屉中 `T-3016`（异设备 D-C1 触点）显示红色「排除」，排除依据明确写出「无跨设备匹配授权」；同页 `O-2001`（P-1001 已授权）则保留 D-A1/D-A2 三台设备触点。

### 场景 2：部分退款与净额计算

- 数据接入页 ③净额管线：`O-2005` 毛额 ¥2,499.00 − 退款 ¥400.00 = 净额 ¥2,099.00，状态 `refunded_partial`；其触点时间带 `America/Los_Angeles` 与 `Asia/Shanghai` 双时区，抽屉按原始时区展示（**跨时区活动**）。
- 切换两个输入快照（页面顶部下拉）可看到净额版本逐版本变化。

### 场景 3：无订单标识点击留在平台汇总区（输入边界）

- 数据接入页 ④「平台汇总区」：5 条日级聚合全部带红色「无」订单标识徽章，费用与点击独立展示，页面明确提示**禁止与订单明细相加**。
- 订单 `O-2006` 无任何订单级触点，报告页中进入紫色「未知来源」单列，不分配给任何渠道；平台汇总里 `A-05` 的备注说明其点击无法关联订单。
- 接入作业 `J-v1-06` 为「已隔离」：缺稳定标识与授权字段的 DSP 补传整批不进入分配。

### 场景 4：五模型并行与敏感性、份额守恒

- 归因运行页「同一快照并行多模型试算」→ 点击后同快照并行计算 5 种模型，堆叠柱图对比渠道结论差异，表格逐模型展示守恒校验。
- 任意运行详情与报告页顶部均可看到不变量：**渠道已分配 + 未知来源 = 参与分配净收入**，每单分摊额严格等于该单净额（整数尾差并入末次触点）。

### 场景 5：两名分析师并行改成交定义（草稿隔离 + 审批核对）

1. 分别切换林岚、高航，各建一个草稿（可选择不同成交定义），运行列表中两条草稿独立存在、创建人各自记录。
2. 进入任一草稿详情，把「规则修订」手动改为与快照不一致的 `RR-2026-04` → 执行计算 → 赵明「审批核对」会被**驳回**（红色「修订不一致」），且「锁定」按钮不可用；改回一致修订后审批通过。

### 场景 6：迟到退款生成新运行，旧分享不变

1. 对场景 0 中已锁定的运行，在 **共享报告** 页（赵明身份）生成一份分享，记录 `O-2002` 冻结净额 ¥899.00。
2. 回到归因运行页，该运行行出现「基于新退款生成新运行」（新快照 `DS-2026-11-05` 含迟到退款 `R-1006`）。新草稿自动列出变化订单 `O-2002` 与「锁定后到达退款」，其净额变为 ¥699.00。
3. 打开旧共享报告：冻结载荷中 `O-2002` 仍为 ¥899.00，图表与明细完全不变；列表标注「已有更新版本，本分享仍保持冻结时结果」。

### 场景 7：筛选切换的旧响应不覆盖新条件（竞态保护）

- 报告页快速连续切换渠道筛选/订单号/运行：页面出现「竞态保护：已丢弃 N 个晚到的旧筛选响应」提示，表格始终对应当前筛选条件（机制见 `RequestSeq`，并有单测覆盖）。归因运行页并行试算面板对快速重复点击有同样保护。

### 场景 8：预算只读已完成运行、模拟不回写

- **预算方案** 页的来源运行下拉只出现 `已完成/已锁定` 运行，草稿与计算中不可选；调整弹性系数与逐渠道预算后产生模拟收入与模拟 ROAS，保存方案后报告页与运行结果数字不发生任何变化。

### 场景 9：从渠道金额回到订单与触点

- 报告页饼图**点击渠道扇区** → 订单表自动筛选该渠道 → 点击订单行 → 抽屉展示净额版本、退款流水、按时间排列的触点旅程、每个触点的合格/排除依据与分摊权重金额。

## 5. 关键约束与实现对照

| 需求约束 | 实现位置 |
| --- | --- |
| 只用授权确定性标识连接设备，未授权不拼人 | `engine/attribution.ts: eligibleTouchpoints` + `data/sampleData.ts` 身份档案 |
| 平台汇总与订单级触点分开保存，前者不参与逐单分配 | 类型 `PlatformClickAggregate` / `Touchpoint`；数据接入页与报告页独立汇总区 |
| 订单份额总和不超过净收入、逐单守恒 | `integerAllocation` 整数尾差收口 + `verifyInvariants`（单测覆盖两快照×五模型） |
| 未知来源订单单列 | 引擎 `unknown` 分支；报告页紫色统计卡与行徽章 |
| 运行绑定时区/成交定义/窗口/规则修订 | `RunConfig`；运行详情 KeyValue 与配置校验和 `configChecksum` |
| 单模型冻结运行 vs 同快照并行多模型 | 运行列表（一次一模型）+「并行多模型试算」面板（不落库） |
| 审批与分享核对来源修订 | `approveRun` 比对快照修订，不一致禁止锁定与分享 |
| 三实体独立状态机 | `AttributionRun.status` / `BudgetPlan.status` / `SharedReport.status` |
| 预算只读已完成运行、不回写订单 | BudgetPage 运行过滤；模拟结果仅存于预算方案 |
| 迟到退款 → 新运行 + 变化订单清单，旧分享冻结 | `diffSnapshots`、`createSupersedingRun`、共享 `frozen` 深拷贝载荷 |
| 旧响应不覆盖新筛选 | `services/api.ts: RequestSeq` + 报告页/试算面板序号守卫 |
| 报告与分享固定引用同一运行/快照 | 运行与共享均保存 `snapshotId/dataVersion/ruleRevision` 并在界面显式展示 |
| 可追溯输入（接入/归并/净额） | 数据接入页血缘表（作业、校验和、隔离）、身份表、净额版本表 |

## 7. 目录结构

```
src/
├── components/      # EChart 封装、通用 UI、订单钻取抽屉
├── data/            # 样例数据（两个数据版本快照、四类边界场景）

├── lib/             # 常量、金额/时间格式化、图表配色
├── pages/           # 数据接入 / 归因运行 / 报告 / 预算 / 共享 五个页面
├── services/        # 模拟异步 API 与 RequestSeq 竞态守卫
├── store/           # zustand 持久化状态（运行、共享、预算生命周期）
├── types/           # 领域模型类型
└── styles/          # 全局样式
tests/               # Vitest 测试
Dockerfile / docker-compose.yml / nginx.conf
```

## 8. 已知边界

- 数据为内置样例，模拟异步延迟（200–800ms）以暴露真实竞态；接入真实后端时替换 `services/api.ts` 即可，领域模型与引擎不变。
- 持久化位于浏览器 localStorage，仅用于单机演示；多分析师并发在真实系统中应由后端乐观锁/版本号承载，本应用通过独立草稿与修订核对表达该规则。
- 预算模拟采用显式弹性规则（公式直接展示在页面上），是方案对比工具，不预测真实收入。
